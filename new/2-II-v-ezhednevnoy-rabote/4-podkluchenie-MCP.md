# ИИ + Git и Подключение сторонних MCP-серверов

Автоматизация работы с системами контроля версий и расширение контекста ИИ с помощью внешних серверов (баз данных, API, локальных и облачных инструментов).

## Автоматизация Git: от хаоса к стандартам

Работа с Git — рутинная, но критически важная часть разработки. ИИ-ассистенты способны анализировать ваши изменения (`git diff`) в реальном времени и автоматизировать создание коммитов и описаний к пулл-реквестам (PR), избавляя от написания бессмысленных сообщений в духе `fix` или `update`.

### 1. Коммиты по стандарту Conventional Commits из git diff
ИИ-инструменты (например, плагины для VS Code или CLI-утилиты вроде `aicommits`) считывают слепок измененного кода перед коммитом. Они понимают логику изменений и автоматически формируют сообщение по строгому стандарту **Conventional Commits**:

`type(scope): description`

::: success Пример генерации: ИИ видит добавление валидации в модуль авторизации и вместо фразы «добавил проверку» генерирует: `feat(auth): add email domain validation for registration flow`. :::

### 2. Автогенерация описаний Pull Request
Когда локальные изменения отправляются на GitHub или GitLab, ИИ собирает дифференциал между ветками и генерирует структурированное саммари для коллег. Грамотное AI-описание PR включает:
* **Сводку изменений (Summary):** Кратко, что было сделано.
* **Список изменений (Changelog):** Пофайловый разбор ключевых правок.
* **План тестирования (Testing Plan):** Что и как нужно проверить ревьюеру.

| Задача в Git | Что делает ИИ | Что контролирует человек |
| :--- | :--- | :--- |
| **Commit Message** | Читает `git diff`, подбирает правильный тип (`fix`, `feat`, `docs`, `refactor`). | Проверяет, не попали ли в коммит лишние временные файлы. |
| **PR Description** | Агрегирует логи всех коммитов ветки, пишет красивый Markdown-отчет. | Корректирует бизнес-контекст (зачем это было сделано для заказчика). |

## Model Context Protocol (MCP): новая эра расширения ИИ

Изначально большие языковые модели (LLM) внутри IDE были изолированы: они видели только текст открытых файлов. **Model Context Protocol (MCP)** — это открытый стандарт, разработанный Anthropic, который позволяет подключить ИИ к любым внешним инструментам, базам данных и API.

С помощью MCP-серверов ИИ-ассистент (например, Cursor или Claude Desktop) превращается из простого генератора кода в полноценного оператора вашей рабочей среды.

### Популярные типы сторонних MCP-серверов:
1. **MCP для Баз Данных (PostgreSQL, MySQL, Redis):** Позволяет ИИ напрямую читать схему вашей БД, выполнять тестовые запросы и проверять, почему падает миграция.
2. **MCP для Инструментов разработки (GitHub, Jira, Linear):** ИИ может сам читать тикеты из Jira, создавать ветки, привязанные к задачам, и оставлять комментарии в PR.
3. **MCP для Системного окружения (Terminal, Filesystem, Docker):** Дает ИИ легитимный доступ к запуску контейнеров, проверке логов Docker и исследованию локальных директорий.


### Практический пример: Подключение ИИ к локальной базе PostgreSQL

Чтобы ваш ИИ-ассистент мог читать таблицы и делать SQL-запросы, в файл конфигурации IDE (например, `mcp_config.json` в Claude или в настройках Cursor) добавляется следующий блок:

```json
{
  "mcpServers": {
    "postgres-local": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-postgres",
        "postgresql://postgres:my_secret_password@localhost:5432/my_project_db"
      ]
    }
  }
}
```

**Как это устроено под капотом:**
* **`command` и `args`:** Запускают официальный мини-сервер MCP для работы с PostgreSQL через Node.js.
* **`postgresql://...`:** Строка подключения к вашей локальной базе данных разработки.

**Что теперь может делать ИИ в чате?**
Получив этот инструмент, ИИ регистрирует у себя набор функций (tools) и при вашем запросе использует их автономно:

> **Пользователь:** Посмотри структуру таблицы пользователей и найди, почему новые юзеры не могут зарегистрироваться.
> 
> **ИИ (вызывает инструмент `list_tables`):** Вижу таблицу `users`.
> 
> **ИИ (вызывает инструмент `describe_table` с аргументом `users`):** Анализирую колонки. Вижу, что поле `phone_number` имеет ограничение `NOT NULL`, но в нашем коде регистрации на бэкенде мы отправляем только `email` и `password`. Вот почему база отклоняет запросы. Исправляю код бэкенда...


::: danger Безопасность превыше всего: подключая сторонние MCP-серверы, проверяйте, какие права вы им даете. Сервер с доступом к терминалу или БД может случайно выполнить деструктивную команду, если промпт будет составлен некорректно. :::

## Принцип работы: ИИ как оркестратор инструментов

В этой парадигме ИИ действует по паттерну **«Мышление -> Выбор инструмента -> Действие -> Анализ результата»**:

1. **Запрос:** *«Проверь, почему юзер с id 42 не может войти, и исправь код»*.
2. **Мышление ИИ:** Мне нужно посмотреть данные юзера в БД и логи бэкенда.
3. **Использование MCP SQL:** ИИ делает запрос в базу через подключенный MCP-сервер PostgreSQL. Видит, что у юзера флаг `is_active = false`.
4. **Использование MCP Filesystem:** ИИ находит в коде метод авторизации, где отсутствует обработка заблокированных пользователей.
5. **Исправление:** ИИ меняет код, запускает через терминал тесты и докладывает о результате.


## Зачем это знать ИТ-специалистам разного профиля?

* **Разработчику:** Вы перестаете тратить время на рутинное описание коммитов и ручной сбор логов. Подключив MCP к локальной БД и инструментам, вы делегируете ИИ глубокий контекстный дебаг.
* **Аналитику:** Используя MCP-серверы для работы с документацией (Confluence, Google Drive), вы можете просить ИИ анализировать изменения в ТЗ, автоматически сопоставлять требования с текущими задачами в Jira и генерировать changelog для бизнеса.
* **QA-инженеру:** Вы можете подключить ИИ через MCP к логам серверов (Kibana, Elastic) или к API тестируемого приложения. Появляется возможность писать промпты вида: *«ИИ, посмотри последние 500-е ошибки в логах контейнера и создай под них баг-репорты в Jira с готовыми curl-запросами»*.

## Шпаргалка для собеседования

* Что такое Conventional Commits и как ИИ помогает в автоматизации Git?
<details>
<summary><b>👉 Посмотреть правильный ответ</b></summary>
Conventional Commits — это стандарт именования коммитов, облегчающий чтение истории и автогенерацию версий (например, <code>feat:</code>, <code>fix:</code>, <code>chore:</code>). ИИ автоматизирует этот процесс, анализируя изменения через <code>git diff</code> и генерируя точные, семантически верные сообщения на основе реального кода, а не абстрактных описаний разработчика.
</details>

* Зачем нужен Model Context Protocol (MCP) в современной ИИ-разработке?
<details>
<summary><b>👉 Посмотреть правильный ответ</b></summary>
MCP — это открытый протокол, который позволяет изолированной языковой модели безопасно подключаться к внешним источникам данных и инструментам (БД, API, файловой системе, терминалу, таск-трекерам). Это расширяет контекст ИИ: модель начинает оперировать не только кодом в редакторе, но и инфраструктурой вокруг проекта.
</details>

* В чем заключается главный риск предоставления ИИ доступа к MCP-серверам баз данных или терминала?
<details>
<summary><b>👉 Посмотреть правильный ответ</b></summary>
Главный риск — безопасность и деструктивные действия. Без должного ограничения прав (Read-Only для продакшена) ИИ в агентском режиме из-за галлюцинации или неточного промпта может выполнить деструктивный SQL-запрос (например, DROP TABLE) или запустить опасную команду в терминале. Человек должен жестко разграничивать доступы для MCP.
</details>
